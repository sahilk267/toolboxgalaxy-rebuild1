# Orbit Dash Runtime Structure

`client/src/pages/OrbitDash.tsx` owns the React page frame and HUD state. `client/src/components/GameCanvas.tsx` owns the Babylon lifecycle and translates runtime callbacks into page state. Gameplay itself is framework-independent:

```text
client/src/game/
├── assets.ts       Generated-art URLs used by the scene
├── GameWorld.ts    Input, player, gates, pickups, score, lifecycle
└── scene.ts        Babylon scene, camera, lights, background, and game handle
```

`GameWorld` owns meshes, input listeners, timing, scoring, game-over, restart, and cleanup. React does not directly mutate Babylon meshes. The game requires no PHP, database, WebSocket, or Node process; the browser stores only its best score in `localStorage`.

## Signal Switch Runtime Structure

Signal Switch will mirror the Orbit Dash lifecycle while staying isolated under `client/src/game/signalSwitch/`. Its React route will own only the HUD, score, sound state, and start/restart action. The Babylon runtime will own the relay-pad meshes, keyboard and pointer input, countdown state, selection validation, high score, and cleanup. Both games share the same browser-first constraints: no server runtime, no automatic audio, no remote score persistence, and a deterministic `?demo` presentation mode.

## Circuit Shift Runtime Structure

Circuit Shift is isolated in `client/src/game/circuitShift/`. Its React route owns only HUD state, sound opt-in, difficulty/mode selection, restart, and result-sharing controls. The framework-independent `CircuitShiftWorld` owns the 4×4 tile orientation array, selection index, path evaluation, procedural mesh highlighting, pointer/keyboard listeners, deterministic demo rotations, score, local best score, and cleanup. Its browser-local `calm`, `standard`, and `dense` profiles alter only deterministic scramble intensity and score multiplier. `dailyChallenge.ts` independently derives sixteen daily offsets from the device-local date; `dailyStreak.ts` persists only consecutive completed local-date IDs/current-longest counts. `localScoreShare.ts` formats only visible completion values—mode, selected difficulty or daily ID, score, moves, and daily streak—and offers native Web Share, copy, and text download fallbacks. The React page renders that control only after a real solved board, never its deterministic demo. The canvas adapter retains the same one-engine, one-scene, resize-safe lifecycle used by the first two games. `client/src/game/registerStandardShaders.ts` explicitly registers Babylon’s default material shader pair before each canvas starts, avoiding blank canvases from deferred shader-module loading.

## Local PWA and route-history structure

`client/public/service-worker.js` handles only same-origin static caching. Its cached update waits until `PwaUpdateNotice` receives an explicit visitor action, then the new worker activates and the page reloads. `client/src/lib/recentToolHistory.ts` persists only recent route metadata from the typed tool registry; `RecentToolHistory` renders its local clear/export controls on the Tools hub. `client/src/lib/favoriteTools.ts` persists only favorite tool slugs; `FavoriteToolButton` and `FavoriteTools` resolve those slugs against the bundled registry for cards, workspaces, and the pinned deck. `ShortcutReference` uses the existing accessible dialog/keycap primitives, opens from a visible rail control or `?` when focus is not in a typing control, and stores nothing. `CommandPalette` uses the prebuilt command/dialog primitives for navigation-only workbench, game, and verified-tool routes; it opens from the visible rail control or Ctrl/Cmd+K only outside editable controls and open dialogs, and stores/searches no user content. Circuit Shift’s global game handler yields whenever an editable control or open dialog owns focus. No user workspace state is collected or exported.

## Logic Lab Runtime Structure

`client/src/pages/LogicLab.tsx` remains an optional six-module catalog at `/games/logic-lab`, while `client/src/pages/LogicPuzzle.tsx` now owns the direct full-screen Games Bay routes `/games/mini-sudoku`, `/games/tango`, `/games/queens`, `/games/patches`, `/games/zip`, and `/games/wend`. The legacy `/games/logic/:slug` route still dispatches the same page. The shared frame owns current-board interaction, reset, verified next-move hints, local validator feedback, date-local assist display, a silent deterministic `?demo=1` state, and only visible pointer/keyboard controls.

The rule ownership is intentionally separated under `client/src/game/logicPuzzles/`: `core.ts` supplies grid helpers; `daily.ts` derives deterministic device-local dates, orientations, and Calm/Standard/Dense profiles; `miniSudokuBank.ts`, `tangoBank.ts`, `queensBank.ts`, `patchesBank.ts`, `zipBank.ts`, and `wendBank.ts` own seven distinct authored editions; `miniSudoku.ts` validates every selected row, column, and 2×3-box field; `tango.ts` validates each selected binary field with its relation map; `queens.ts` validates each selected 6×6 connected-region constraint board; `patches.ts` validates each selected 6×6 clue-owned rectangle exact cover and counts partitions; `zip.ts` validates every selected wall-respecting path and counts paths; and `wend.ts` validates each selected locally authored orthogonal target-word path set and counts exact covers. `LogicPuzzle.tsx` selects all six puzzle editions from their bundled seven-day banks using the device-local date, carries actual edition difficulty into the HUD, positions Tango relations, Queens map telemetry, Patches partition telemetry, and Wend word-cover telemetry, and persists completion under the edition ID plus date so records cannot mix. `scripts/verify-logic-puzzles.ts` asserts all six known solutions, relevant invalid mutations, daily-transform round trips, every Mini Sudoku, Tango, Queens, Patches, Zip, and Wend field’s unique solution, their non-repeating topology signatures, and seven-consecutive-date selection coverage. None of these modules uses a remote puzzle feed, API, dictionary request, or server runtime.

`puzzleCompletion.ts` remains the sole owner of the existing browser-local completion map and now exposes a read-only snapshot for derived UI. `weeklyLogicStreak.ts` parses only the known edition-specific Mini Sudoku, Tango, Queens, Patches, Zip, and Wend completion prefixes, groups those fields by device-local date, and derives all-fields or one selected game’s week cells plus current/longest streaks without writing another record. `logicPersonalBest.ts` cross-checks each route-plus-edition key against its actual seven-field bundled bank, rejects malformed, legacy, unknown, and future records, then derives only per-game completed-edition counts and local-date runs. `weeklyLogicShare.ts` formats only the already visible range, scope, and derived metrics, owns native-share/clipboard/download guards, and cannot read or include completion keys, edition IDs, board paths, or hidden records. `LogicPersonalBestSummary.tsx` owns the six linked personal-record cards; `WeeklyLogicCalendar.tsx` owns in-memory `All fields`/selected-game and Grid/Timeline presentation controls, the genuine-progress-gated share card, week navigation, and explicit local-only/no-match copy. Both the filter and visual arrangement reset on a page load, while the two arrangements consume the same semantic local-day list and derived data. The pure regressions are `scripts/verify-weekly-logic-streak.ts`, `scripts/verify-logic-personal-bests.ts`, and `scripts/verify-weekly-logic-share.ts`; `CALENDAR_ONLY=1` adds real CDP pointer and keyboard tests for aggregation, exclusions, filtering, Grid/Timeline equivalence and reset, personal-best navigation, sharing fallbacks, and navigation inside `games-bay-playtest.ts`.

`client/src/game/audio.ts` owns the shared local `toolboxgalaxy:game-sound` master preference for Orbit Dash, Signal Switch, Circuit Shift, and Logic Lab; `GameAudioControls.tsx` is the corresponding common HUD control. Optional Logic Lab music uses a managed static MP3 reference and a separate local `toolboxgalaxy:logic-music` preference. Sound and music never autoplay: both require an explicit visitor gesture, and disabling master sound pauses optional music.

## Daily Tool Batch 1 Structure

`client/src/data/toolRegistry.ts` remains the typed single registry for every public Tool Foundry card, direct route, favorites, and recent-route entry. Its Batch 1 additions use five unique `ToolKind` values: `businessDays`, `timeZone`, `timestamp`, `textDiff`, and `findReplace`; the Tools hero derives its verified-module telemetry from the registry length rather than a stale hard-coded total. `client/src/lib/dailyToolEngines.ts` owns pure business-weekday, browser-time-zone, Unix timestamp, line-diff, and literal/regex replacement behavior. It does not access browser storage, a network service, a current remote clock, or a provider.

`client/src/components/DailyToolRunners.tsx` owns controlled, accessible workspaces, current-view-only reset/copy feedback, concise limitation notices, and semantic output labels. `ToolWorkspace.tsx` only imports and maps those runners through the existing `runnerByKind` dispatcher; it keeps recent-route metadata and optional favorites separate from the user-entered tool content. `scripts/verify-daily-tools.ts` checks pure result/error paths plus complete registry uniqueness; `scripts/playtest-daily-tools.ts` runs actual browser direct-route, pointer, keyboard, native date/datetime input, reset, copy, and output checks.

## Daily Tool Batch 2 Structure

Batch 2 extends the same typed registry and `dailyToolEngines.ts` with three additional unique runner kinds: `splitBill`, `loanEmi`, and `workShift`. `splitBillAndTip` validates non-negative input, a 0–100% chosen tip, and a whole-person count; `estimateLoanEmi` derives a local fixed-rate equal-monthly-payment estimate, handles zero rate separately, and rejects unsafe amount/rate/term bounds; `calculateWorkShift` calculates same-day or cross-midnight minutes after a shorter unpaid break. The engines know no currency rate, lender, payment, timeclock, calendar, payroll, or storage system.

`DailyToolRunners.tsx` supplies three module-specific signatures—allocation matrix, payment projection, and time ledger—plus a primary answer treatment above subordinate breakdowns. `ToolWorkspace.tsx` maps their current state to matching offset header telemetry. The visible Loan / EMI disclaimer is part of the runner contract, not a generalized recommendation surface. The shared browser test verifies the associated direct routes and controls, while the deterministic test extends the same all-tool registry uniqueness check from 29 to 32 entries.

## Structured Data Tool Batch 3 Structure

`client/src/lib/structuredDataEngines.ts` owns all Batch 3 pure operations: bounded CSV character/row/field validation; quoted-cell, escaped-quote, and embedded-newline parsing; header uniqueness and rectangularity checks; spreadsheet-safe CSV serialization; a 12×12 preview shape; tabular flat-object JSON conversion; CSV-to-JSON serialization; and in-memory trim/remove-blank-row cleanup. It has no browser storage, DOM, API, upload, or server dependency. Formula-looking cells are represented as inert strings in the table model and acquire a leading apostrophe only when CSV is exported.

`client/src/components/StructuredDataRunners.tsx` owns controlled current-tab UI state, explicit copy/download/reset controls, the converter direction selector, cleaner settings/counters, Apply clean copy, concise privacy limits, and the accessible `scope="col"` table preview. `ToolWorkspace.tsx` only maps the unique `jsonCsv` and `csvViewer` kinds. The global typed registry remains the source of tool cards, direct routes, quick-open entries, favorites, and recent metadata, and the command-palette count derives from its current length.

`scripts/verify-structured-data-tools.ts` proves the parser and serializer contract, unioned JSON fields, malformed input rejection, cleanup counters, formula-text export guard, preview bounds, input limit, and 34-entry unique registry. `scripts/playtest-daily-tools.ts` adds actual Chromium checks for both direct routes, keyboard-pasted data, invalid JSON/CSV, pointer direction/clean actions, semantic output tables, copy/download/reset feedback, and unchanged browser storage snapshots.

## Image Tool Batch 4 Structure

`client/src/lib/localImageTransform.ts` owns framework-independent still-image limits, source crop-window clamping, right-angle output dimensions, rotation cycling, output extensions, and pre-decode file/dimension errors. Its 20 MB, 8,192px-edge, and 20-million-pixel limits bound browser work; the pure module neither creates URLs nor touches canvas, browser storage, a network, or a server.

`client/src/components/ImageTransformTool.tsx` owns the current-tab File/object-URL lifecycle, source decoding, controlled source-pixel crop fields, explicit crop presets, rotation, canvas rendering, output URL lifecycle, PNG/JPG/WebP settings, user-triggered download, Reset edit, and accessible preview/error state. It revokes superseded/unmounted source and output object URLs. `ToolWorkspace.tsx` maps only the unique `imageTransform` kind and module-specific FRAME CUTTER telemetry. The static page contains no upload adapter: local `File`/canvas/blob data never enters the recent-tool/favorites metadata helpers.

`scripts/verify-image-transform.ts` validates pure crop/rotation/format/boundary rules plus unique 35-entry registry. `scripts/playtest-image-transform.ts` drives a genuine Chromium file input, crop dimensions, rotation, format/quality, local canvas output, download anchor, reset, unsupported-file response, and unchanged local-storage snapshot.

## Text Utility Batch 5 Structure

`client/src/lib/lineToolEngine.ts` owns framework-independent current-tab text limits, line-ending normalization, trim/blank/duplicate policy, deterministic original-index tie handling, alphabetical/descending/first-seen order, and summary counters. It receives a single in-memory string and returns only an output string/counts or a bounded-input error; it cannot call a network, storage API, file system, or server.

`client/src/components/LineToolRunner.tsx` owns controlled textarea/options, rendered counters, explicit browser clipboard/download actions, reset feedback, and clear local limitation copy for the unique `lineSorter` runner kind. `ToolWorkspace.tsx` only supplies the `SEQUENCE CLEANUP` telemetry and route mapping. `scripts/verify-line-tool.ts` validates exact ordering, trim/case/blank behavior, bounds, and unique 36-entry registry. `scripts/playtest-line-tool.ts` uses real Chromium keyboard input and pointer control changes, observes explicit download/copy/reset behavior, and verifies no local-storage record or request is created.


## Image Tools Batch 6 Structure

`client/src/lib/localImageMetadata.ts` owns framework-independent supported-type checks, file/decoded-pixel bounds, native-dimension re-export rules, and honest clean-output metadata boundary. It has no canvas, FileReader, object-URL, storage, network, or server dependency.

`client/src/components/ImageMetadataTool.tsx` owns the controlled current-tab file picker, source decoding, native-dimension canvas re-export, source/output object-URL cleanup, explicit clean-output action, download, Reset, unsupported/decode error state, and accessible privacy limitation copy for the unique `imageMetadata` runner kind. It provides no crop, rotation, resize, format, quality, upload, or source-file mutation flow. `ToolWorkspace.tsx` only maps the unique route and `CLEAN RE-EXPORT` telemetry.

`verify-image-metadata.ts` validates supported formats, file/pixel bounds, native output dimensions, clean re-export assumptions, and 37-entry registry uniqueness. `playtest-image-metadata.ts` drives real Chromium local file selection, pointer clean re-export/download, keyboard clear, unsupported-file feedback, and unchanged local-storage/network state.
